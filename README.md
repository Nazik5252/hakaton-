# MTS CallGuard — backend для МТС Беларусь

Это версия прототипа, в которой frontend подключён к реальному backend.

## Что уже работает

- сайт открывается через Node.js backend;
- звонки хранятся в `data/db.json`;
- frontend получает историю с `/api/calls`;
- изменения категории, приоритета и резюме сохраняются на сервере;
- backend принимает события телефонии на `/api/mts/callback`;
- callback принимает JSON, form-urlencoded и GET query;
- исходные события МТС сохраняются в `data/mts-events.ndjson`;
- backend пытается нормализовать номер, идентификатор звонка, статус, запись и текст;
- если callback содержит текст разговора/расшифровку, выполняется простая классификация;
- кнопку «Перевести в Telegram» обслуживает backend через Telegram Bot API;
- есть локальный тест callback без МТС.

## Что важно понимать

Публичная документация МТС Беларусь подтверждает наличие REST API для интеграции ВАТС с внешними системами, а также Management API/Data API. В личном кабинете интеграции выдаются «Адрес ВАТС» и «Ключ для авторизации», а также указывается внешний адрес вашей системы.

Точный набор полей callback зависит от сценария REST API, который вы включите в ВАТС. Поэтому этот backend сохраняет сырой payload в `data/mts-events.ndjson` и поддерживает несколько распространённых названий полей. После первого реального события достаточно открыть этот файл — по фактическому payload можно точно подогнать нормализацию.

Backend НЕ имитирует реальный перевод активного звонка через API. Для живого перевода/голосового ИИ потребуется конкретная команда Management API либо SIP-сценарий. Без API-контракта и доступов МТС такую команду нельзя корректно «угадать».

# 1. Запуск

Нужен Node.js 18+.

В Windows можно просто дважды нажать:

`start.bat`

Или в PowerShell:

```powershell
node server.js
```

После запуска:

- сайт: `http://localhost:3000`
- проверка backend: `http://localhost:3000/api/health`

Не открывайте `index.html` двойным кликом.

---

# 2. Проверка без МТС

1. Запустите `start.bat`.
2. Запустите `test-mts-callback.bat`.
3. Обновите сайт.

В «Истории» появится тестовый звонок `+375291112233`.
Он показывает, что цепочка:

`callback → backend → БД → frontend`

работает.

---

# 3. Telegram

Откройте `.env` и заполните:

```env
TELEGRAM_BOT_TOKEN=ваш_новый_токен
TELEGRAM_CHAT_ID=числовой_chat_id
```

После изменения `.env` перезапустите `start.bat`.

Проверить можно на странице:

`http://localhost:3000/api/health`

Должно быть:

```json
"telegramConfigured": true
```

На сайте:

`Демо звонка → Запустить демо → Перевести в Telegram`

---

# 4. Подключение МТС Беларусь ВАТС

В личном кабинете Виртуальной АТС МТС:

1. Откройте настройки интеграции с CRM / своей CRM.
2. Включите API.
3. Сохраните:
   - адрес ВАТС;
   - ключ авторизации.
4. Их можно записать в `.env`:

```env
MTS_VATS_BASE_URL=...
MTS_VATS_API_KEY=...
```

Сейчас эти значения сохранены для следующего шага — исходящих запросов Management/Data API. Секреты в frontend не передаются.

## Внешний адрес backend

МТС не сможет обратиться к:

`http://localhost:3000`

Нужен публичный HTTPS адрес.

Например, через ngrok/cloudflared или сервер/VPS:

`https://callguard.example.com`

В настройке REST API ВАТС внешний callback задайте:

`https://callguard.example.com/api/mts/callback?secret=ВАШ_MTS_CALLBACK_SECRET`

`MTS_CALLBACK_SECRET` указывается в `.env`.

Пример:

```env
MTS_CALLBACK_SECRET=my-long-random-secret
```

После этого входящие события МТС будут приниматься backend.

# 5. Как понять, что МТС реально прислала событие

После звонка смотрите:

`data/mts-events.ndjson`

Каждая строка — одно полученное событие.

Также откройте:

`http://localhost:3000/api/calls`

Если callback успешно распознан, звонок появится в JSON и в интерфейсе.

---

# 6. Записи звонков

Backend умеет сохранить ссылку на запись, если REST callback/API передаёт одно из полей:

- `record_url`
- `recordUrl`
- `recording_url`
- `recordingUrl`
- `record`

У МТС Беларусь запись разговоров включается отдельно в ВАТС. Корпоративные SIM, подключённые к ВАТС, также попадают в историю/статистику, а записи могут передаваться по API.

---

# 7. Расшифровка и ИИ

В текущей версии классификация срабатывает, если МТС или внешний STT передаёт backend текст в одном из полей:

- `transcript`
- `text`
- `speech_text`

Для полноценной автоматической расшифровки аудиозаписи нужен отдельный Speech-to-Text сервис. В публичной документации МТС Беларусь, которую мы использовали для этой сборки, подтверждена передача записей по API, но мы не стали придумывать несуществующий/непроверенный endpoint транскрибации.

После получения фактического API-контракта или выбора STT сервис можно подключить к этому backend.

# 8. API проекта

### Проверка

`GET /api/health`

### Звонки

`GET /api/calls`

`POST /api/calls`

`PATCH /api/calls/:id`

### Telegram

`POST /api/calls/:id/telegram`

### Настройки

`GET /api/settings`

`PUT /api/settings`

### МТС

`GET|POST /api/mts/callback`

Локальный тест:

`POST /api/mts/test-event`

# Что требуется для следующего этапа

Чтобы сделать именно **реальный перевод активного звонка**, а не только историю/запись/Telegram:

1. получить доступ к API-порталу `api.vats.mts.by`;
2. скачать/показать контракт конкретных методов Management API/Data API;
3. либо получить SIP-данные сотрудника/АТС и строить голосовой сценарий через SIP.

Секретные API-ключи присылать не нужно. Достаточно прислать скриншот/файл документации с названиями методов и параметрами.
